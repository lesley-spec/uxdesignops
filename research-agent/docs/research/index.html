1. Empathize

Status: Built

What this is

Empathize is stage 1 of the design thinking pipeline: gather and make sense of user evidence before we frame a problem. A scheduled agent (Research Insight Monitor) pulls signals from PostHog, Pendo, Outset, and Dovetail and publishes a research pack. On-demand skills let you dig deeper in Cursor, Claude, Figma Agent, or any Agent Skills harness — connect the same MCPs in your harness and ask questions with those skills. AI gathers and narrates. You decide if something is a problem worth solving.

How to use it

  1. Open the latest research report.
  2. Connect the same MCPs in your harness (PostHog, Pendo, Dovetail, Outset, Confluence/Jira) — then use the skills to ask questions in Cursor, Claude, Figma Agent, or any Agent Skills client.
  3. Install a skill folder into your harness skills path (see Pack README), then invoke by name — e.g. “use data-analyze: why is PublisherPro link gen dropping?”
  4. Pick a finding and deep-dive / triangulate with the skill that fits.
  5. At the human gate, confirm or reject “problem worth solving” before Define.

Agent (scheduled)

Research Insight Monitor

Runs on a schedule in research-agent/. Pulls PostHog funnels + Pendo/Dovetail/Outset context, synthesizes findings, publishes to GitHub Pages / Confluence / Slack. High confidence only when 2+ sources agree. You do not start this manually for day-to-day work — use the skills when you need depth on a finding.

2. Define

Status: Built

What this is

Define is stage 2: turn a confirmed “problem worth solving” into a framed one-pager (and optional PRD depth) with dual Brand + Partner lenses, then link it in Confluence and a UX Jira epic. AI drafts from FigJam conventions, prior chats, and Empathize evidence. You confirm before anything is created. When the Designer is happy with the framing, they chat with a PM before Ideate.

How to use it

  1. Only after the Empathize gate: problem confirmed worth solving.
  2. In Cursor/Claude: “use write-spec on [finding]” — it pulls FigJam, chats, and the research pack.
  3. Review the draft one-pager (Brand + Partner lenses + anti-sycophancy).
  4. Confirm to publish: Confluence page in space ux + UX Epic with research links.
  5. When the Designer is happy with framing, chat with a PM before Ideate.

3. Ideate

Status: Built

What this is

Ideate is stage 3: diverge from framing into solution directions. Prefer a one-pager or detailed PRD; epic, tickets, Granola/meeting notes, or chat paste also work (label gaps). AI prompts for fidelity and tool, emits an ideation brief, and seeds wires or mock prompts. You iterate in FigJam, Figma Make, Cursor, Claude, or Stitch — then critique coverage before Prototype.

How to use it

  1. After Designer + PM chat on framing (or explicit override).
  2. In Cursor/Claude/Figma Agent: “use ideate on [epic/one-pager/notes]” — it pulls sources, asks fidelity/surface/# directions, then drafts a brief + starter concepts.
  3. On-brand mocks → Figma Make or Cursor + design-system; wires → Claude/FigJam; variations → Figma Agent or Google Stitch.
  4. Mid-loop or before exit: “use ux-critique”.
  5. When happy with mocks: “use prototype-handoff”.

4. Prototype

Status: Built

What this is

Prototype is stage 4: turn a confirmed Ideate direction + mocks into a running impact.com UI shell on your machine. One prompt runs brand-prototype or partner-prototype — the agent executes scripts/bootstrap.sh (clone public template, npm install, start Vite). You paste Figma mocks and build on top with Styleguide V2. Cursor-first. Figma Make cannot clone repos — route to Cursor or a labeled Make click-through.

How to use it

  1. After prototype-handoff is confirmed.
  2. In Cursor: “use brand-prototype” or “use partner-prototype”. Agent runs bootstrap automatically — no manual git/npm checklist.
  3. Default folders: ~/Documents/impact-prototypes/brand-ui and …/partner-ui.
  4. Brand opens http://localhost:5174/one-program-1/ · Partner http://localhost:5173/.
  5. Then paste mock links + ask AI to implement screens. Use design-system for Styleguide V2.

5. Test

Status: Skills built

What this is

Test is stage 5: validate prototypes with users and synthetic pre-tests. Draft Outset or Maze studies from a prototype plus one-pager success criteria; run synthetic pre-flight before recruiting. After sessions, test-loopback publishes Verified findings back to Empathize.

How to use it

  1. After the Prototype gate (prototype URL ready).
  2. In Cursor/Claude: “use test-plan on [prototype link]” — it runs synthetic pre-tests, then drafts an Outset/Maze study.
  3. Designer publishes to Outset/Maze; review all AI output before stakeholders.
  4. After sessions: “use synthesize-research” on the corpus, then “use test-loopback” to Confluence/Jira.
