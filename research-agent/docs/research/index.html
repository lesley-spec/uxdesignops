Once the pack is in, design-thinking-ux is the guided run. It asks what you are working on and where you already are, then walks Empathize (evidence) → Define (one-pager and UX epic) → Ideate (directions and critique) → Prototype (Brand or Partner live shell) → Test (study plan). It invokes the skill for the current stage in the same chat and stops at each human gate — you confirm a problem worth solving, publishing, a chosen direction, and recruiting. Join mid-pipeline if you already have research, a spec, mocks, or a prototype. Verified test findings loop back to Empathize.

1. Empathize

Status: Built

What this is

Empathize is stage 1 of the design thinking pipeline: gather and make sense of user evidence before we frame a problem. A scheduled agent (Research Insight Monitor) pulls signals from PostHog, Pendo, Outset, and Dovetail and publishes a research pack. On-demand skills let you dig deeper in Cursor, Claude, Figma Agent, or any Agent Skills harness — connect the same MCPs in your harness and ask questions with those skills. AI gathers and narrates. You decide if something is a problem worth solving.

How to use it

  1. Not installed yet? Install the skills first, then “use Design Thinking UX”.
  2. Prefer the master skill: “use Design Thinking UX” — it asks if you have research and invokes Empathize skills for you.
  3. Open the latest research report or the monthly Brand & Partner usage snapshot.
  4. Connect the same MCPs in your harness (PostHog, Pendo, Dovetail, Outset, Confluence/Jira) — then use the skills to ask questions in Cursor, Claude, Figma Agent, or any Agent Skills client.
  5. Or invoke a single Empathize skill by name — e.g. “use data-analyze: why is PublisherPro link gen dropping?”
  6. At the human gate, designer and UX researcher confirm or reject “problem worth solving” before Define.

Agent (scheduled)

Research Insight Monitor

Runs on a schedule in research-agent/. Pulls PostHog funnels + Pendo/Dovetail/Outset context, synthesizes findings, publishes to GitHub Pages / Confluence / Slack. High confidence only when 2+ sources agree. You do not start this manually for day-to-day work — use the skills when you need depth on a finding.

2. Define

Status: Built

What this is

Define is stage 2: turn a confirmed “problem worth solving” into a framed one-pager (and optional PRD depth) with dual Brand + Partner lenses, then link it in Confluence and a UX Jira epic. AI drafts from FigJam conventions, prior chats, and Empathize evidence. You confirm before anything is created. When the Designer is happy with the framing, they chat with a PM before Ideate.

How to use it

  1. Only after the Empathize gate: problem confirmed worth solving — or let design-thinking-ux entice Define and invoke write-spec.
  2. In Cursor/Claude: “use Design Thinking UX” (master) or “use write-spec on [finding]” — it pulls FigJam, chats, and the research pack.
  3. Review the draft one-pager (Brand + Partner lenses + anti-sycophancy).
  4. Confirm to publish: Confluence page in space ux + UX Epic with research links.
  5. When the Designer is happy with framing, chat with a PM before Ideate.

3. Ideate

Status: Built

What this is

Ideate is stage 3: diverge from framing into solution directions. Prefer a one-pager or detailed PRD; epic, tickets, Granola/meeting notes, or chat paste also work (label gaps). AI prompts for fidelity and tool, emits an ideation brief, and seeds wires or mock prompts. You iterate in FigJam, Figma Make, Cursor, Claude, or Stitch — then critique coverage before Prototype.

How to use it

  1. After Designer + PM chat on framing (or explicit override) — or continue from design-thinking-ux.
  2. In Cursor/Claude/Figma Agent: “use Design Thinking UX” (master) or “use ideate on [epic/one-pager/notes]” — it pulls sources, asks fidelity/surface/# directions, then drafts a brief + starter concepts.
  3. On-brand mocks → Figma Make or Cursor + design-system; wires → Claude/FigJam; variations → Figma Agent or Google Stitch.
  4. Mid-loop or before exit: “use ux-critique” (the master skill invokes this before handoff).
  5. When happy with mocks: “use prototype-handoff”.

4. Prototype

Status: Built

What this is

Prototype is stage 4: turn a confirmed Ideate direction + mocks into a running Brand or Partner UI shell in the harness you are in (Cursor, Claude, or Figma Make). One prompt runs ux-prototyping — live preview here (localhost, Make canvas, or Claude artifact), then you can publish a GitHub repo on your own account for Pages. Paste Figma mocks and build with Styleguide V2. Do not switch tools to finish Prototype.

How to use it

  1. After prototype-handoff is confirmed — or continue from design-thinking-ux.
  2. In Cursor, Claude, or Figma Make: “use Design Thinking UX” or “use ux-prototyping”. The agent stays in this harness and gets Brand or Partner running — no “please open Cursor” detour.
  3. Default folders: ~/Documents/impact-prototypes/brand-ui and …/partner-ui.
  4. Brand opens http://localhost:5174/one-program-1/ · Partner http://localhost:5173/.
  5. Then paste mock links + ask AI to implement screens. Use design-system for Styleguide V2.

5. Test

Status: Skills built

What this is

Test is stage 5: validate prototypes with users and synthetic pre-tests. Draft Outset or Maze studies from a prototype plus one-pager success criteria; run synthetic pre-flight before recruiting. On designer confirm, test-plan creates an Outset draft via MCP — it does not launch recruitment. After sessions, test-loopback publishes Verified findings back to Empathize.

How to use it

  1. After the Prototype gate (prototype URL ready) — or continue from design-thinking-ux.
  2. In Cursor/Claude: “use Design Thinking UX” (master) or “use test-plan on [prototype link]” — it runs synthetic pre-tests, then drafts an Outset/Maze study.
  3. Connect Outset MCP at https://api.outset.ai/mcp/ (OAuth). On confirm, the skill creates an Outset draft. Do not recruit unless you ask. The v1 API key only lists studies.
  4. Designer and UX researcher review all AI output before stakeholders.
  5. After sessions: the master skill invokes synthesize-research then test-loopback — or call those skills directly.
