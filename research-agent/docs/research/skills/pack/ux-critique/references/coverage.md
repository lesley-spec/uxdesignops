# Coverage matrix guidance

## What counts as a framing item

- Problem / opportunity statements
- JTBD and ranked pains
- Success criteria (quant/qual)
- In/Out scope
- Epic description + linked ticket acceptance criteria
- Explicit constraints from notes (legal, marketplace, tech)

Skip fluff, agenda lines, and duplicate paraphrases — merge duplicates into one row.

## Status values

| Status | Meaning |
|---|---|
| **addressed** | Clear treatment in mocks |
| **partial** | Touched but incomplete vs source |
| **missing** | Not visible in reviewed artifacts |

## Severity

| Severity | Handoff rule |
|---|---|
| **Critical** | Blocks `prototype-handoff` unless designer accepts residual risk in writing |
| **Major** | Prefer fix; may defer with explicit note in handoff pack |
| **Minor** | Polish; does not block |

## vs anti-sycophancy

`anti-sycophancy` = is the **problem** well framed?  
`ux-critique` = do the **solutions** cover what we already agreed?
