# Rigor at speed — sample, diversity, and the 3-participant pass

Speed does not have to cost rigor. It costs rigor when nobody looks at the early
data, and when the sample is eight versions of the same person.

---

## Sample sizes

| Mode | Target | Minimum | Notes |
|---|---|---|---|
| **MICRO** | 8–15 | 5, if patterns are crystal clear from the first 3 | Past 15, diminishing returns |
| **SPRINT** | 15–20 Outset **+ 5** human follow-ups | — | Outset runs 7–10 days; follow-ups days 7–10 |
| **DEEP** | 12–15 | 8 if the segment is homogeneous | Multi-segment: 5–7 **per segment** |

Follow-ups in SPRINT are **5 of the 15–20**, not all of them. You are digging
into themes the study surfaced, not re-interviewing everyone.

---

## Minimum viable diversity

The goal is to understand the **space**, not represent the population. That is
quantitative work and it is not what this is.

But you need **variation**, or you learn one thing very thoroughly.

| | |
|---|---|
| ✅ | 8 admins · managing 1–100 accounts · self-serve through sales-led · technical through non-technical |
| ❌ | 8 admins · all technical · all managing 50–100 accounts · all from the same company size |

The second gives you **one story told eight times**, and it will feel like strong
agreement. That is the trap: homogeneous samples produce high apparent
consensus, which reads as confidence in the readout.

Pick the two or three dimensions most likely to change the answer — tenure,
scale, workflow, technical confidence — and deliberately spread across them.

---

## The 3-participant pass

**Review the first three end-to-end before the rest runs.** No mode skips it.

The point is not quality control. It is noticing, while it is still cheap, that
the study is asking the wrong thing.

### MICRO

1. Run the first 3 responses
2. Read the **raw** responses, then the AI summary — in that order
3. Ask: did the summary miss nuance? Are these patterns real or am I seeing one?
4. Clear → run the remaining 5–12. Flawed → fix before anyone else sees it

### SPRINT

1. Run the first 3 Outset sessions
2. Read transcripts alongside the AI analysis
3. Identify 2–3 themes worth probing deeper
4. Write specific probes for the human follow-ups from what you saw
5. Proceed

The pass is what makes the follow-ups worth having — without it you book five
calls and improvise, which is five more participants spent on the same surface.

### DEEP

1. Conduct the first 3 interviews end-to-end, **including synthesis**
2. Review all raw data together — watch replays, read transcripts
3. Revise the guide
4. Run the rest with the improved guide

Synthesising three before running twelve is what stops a guide's blind spot being
baked into the whole study.

---

## The three outcomes

Record which, and why, on the ticket:

| | Means |
|---|---|
| **Proceed** | Patterns are forming, questions are landing, run the rest |
| **Fix** | Question is right, instrument is wrong. Revise probes or guide, then continue |
| **Pivot** | The question itself is wrong. Back to hygiene — possibly back to intake |

**Pivot is a success.** Three participants spent discovering the question was
wrong is the cheapest version of that discovery. The expensive version is
fifteen participants and a readout nobody can act on.

> "Set boundaries. Build in rigour with probes and instructions."

This isn't gatekeeping. It is what protects the team from running a study and
learning nothing.
